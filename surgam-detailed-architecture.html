Architecture Scope & Regulatory Grounding

This document establishes the production cloud topology, microservice interactions, and relational database schema for Surgam Capital's B2C direct wealth and B2B distributor network platform (AMFI registered MFD). It strictly decouples four specialized client surfaces, enforces cryptographic channel ownership, and specifies 18 core relational database tables with row-level security (RLS) under SEBI, AMFI, and DPDP Act frameworks.

The Four Decoupled Application Surfaces
1. Investor App & Web B2C & B2B Clients
Users: Direct Investors & Partner Clients
  • Dynamic Co-Branding: Automatically loads partner logo, ARN, and EUIN for partner clients.
  • Wealth Dashboard: XIRR, goal-based SIPs, holding breakdown, and capital gains statements.
  • Trade Approval: In-app, SMS, and WhatsApp OTP authorization with tax-impact previews.
  • Empower Her: Dedicated female-investor goal spaces and confidential privacy within family accounts.
Data Boundary: Encrypted PAN lookup; scoped strictly to verified family group / investor ID.
2. Partner Desk (Web & Mobile) Distributor B2B
Users: Partner Distributors & Sub-Staff
  • Practice Management: Real-time AUM, net sales, live SIP books, and client 360 views.
  • Assisted Initiation: Order builder generating secure 24-hour investor approval links.
  • Automated To-Dos: Proactive alerts for failed SIPs, expiring KYC, and annual reviews.
  • Payout Drill-down: Full folio-level reconciliation for Model A/B brokerage payouts.
Data Boundary: Database Row-Level Security (RLS) restricts access strictly to mapped sub-ARN folios.
3. Operations & Compliance Console Back-Office
Users: Operations Executives, Compliance Officers, Finance
  • Maker-Checker Engine: Segregated approval queues for overrides, master data, and payouts.
  • Surveillance & AML: Churn detection (<12m switches) and redemption post-bank change alerts.
  • Feed Reconciliation: Automated matching of daily CAMS/KFintech feeds against exchange trades.
  • Grievance Helpdesk: Integrated ticketing with strict 5, 7, and 21-day SEBI escalation timers.
Data Boundary: Internal desktop only; PAN/Bank details masked by default based on role.
4. Platform Administration SecOps & Tech Leads
Users: CTO, Platform Engineers, SecOps
  • Configuration Engine: AMC rate cards, commission models, and cut-off schedules.
  • Consent Vault: Complete DPDP digital consent store, usage purpose, and revocations.
  • 8-Year Audit Explorer: Query access to WORM-compliant immutable ledger for SEBI inspections.
  • Secrets & Key Vault: AWS KMS key rotation, API rate-limiting, and feature flag management.
Data Boundary: Hardware FIDO2 MFA + IP Whitelist. No direct financial write capabilities.
Decoupling Guarantees & Channel Integrity
Channel-Conflict Guard (CMP-07)

Surgam Relationship Managers (RMs) are cryptographically restricted from querying or viewing clients tagged to Partner MFDs. Even if an RM searches an investor's PAN, the system returns zero results if tagged to a partner.

Hard Suitability Enforcement (CMP-01)

Software automatically blocks orders where a fund's Risk-o-meter exceeds the investor's verified risk score. Overrides require dual-authorization and recorded investor acknowledgement before reaching the exchange.

Disaster Recovery & High-Availability Mandate (SEC-01)

Storage-level cross-region continuous replication via Amazon Aurora Global Database to ap-south-2 (Hyderabad). Replicates all financial transactions, folios, and mandates with sub-second replication latency.

Open Architectural & Strategic Queries

The following architectural and operational decision points are kept open for executive and stakeholder resolution:

Query 1: Transaction Rail Integration Model (Direct vs Managed API Layer)
Decision Point: Integrate directly with BSE StAR MF / NSE NMF II (exchange membership via Surgam's ARN) vs buy a unified transaction API layer (such as Fintech Primitives by Cybrilla or smallcase Gateway).
• Direct Exchange Integration: Zero per-transaction API markups; higher upfront integration effort and ongoing exchange schema maintenance.
• API Layer: Reduces launch effort by ~5 person-weeks; adds per-transaction recurring vendor fees.
Query 2: Feed Ingestion & Portfolio Valuation Engine (Build vs Buy API)
Decision Point: Parse daily CAMS and KFintech SFTP feeds and calculate XIRR/capital gains in-house vs utilize mature back-office calculation APIs (e.g., Investwell or REDVision Wealth Elite).
• In-House Engine: Full control over calculation nuances and complete data sovereignty without external export dependencies.
• Back-Office Vendor API: Pre-built handling of edge cases (corporate actions, mergers), saving ~5 person-weeks.
Query 3: Suitability Enforcement Thresholds (Hard Block vs Recorded Consent)
Decision Point: Determine whether orders where fund Risk-o-meter exceeds investor risk level should be completely blocked by software, or permitted for non-vulnerable investors if accompanied by explicit, recorded digital consent.
• Recommended Hybrid: Hard block for vulnerable investors (age > 60, declared distress); recorded consent + compliance review queue for standard investors.
Query 4: AI LLM Boundary (Bedrock Claude vs Local Indic Models)
Decision Point: Run conversational support and review pack generation via Amazon Bedrock (Claude 3.5 Sonnet) vs deploy dedicated Indian open models (e.g. Sarvam AI) within VPC subnets for vernacular Hindi/Marathi processing.
